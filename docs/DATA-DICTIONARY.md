# 产线停机裁决与效率重算数据定义

计划分钟=运行分钟+有效停机分钟。班次总分钟=计划分钟+休息并集分钟。总产=良品+废品。起止时间使用含偏移的ISO格式，班次最长24小时。区间采用[start,end)，超出班次的停机裁剪，重叠休息只扣一次。total与good为整数件，ideal_seconds为每件理想秒数。零计划、零运行、零产量分别给出状态，不以任意分母补零。

班次按休息与停机所有端点切片，先扣休息并集，再按安全、故障、换型优先级分配停机。OEE使用未舍入的三因子计算，并保留超产异常。

停机原因采用两种口径，并以同一份切片结果同时给出，停机裁决页与效率结果共用：

- 扣减口径（`causes`/`primary`）：同一分钟内只归最高优先级原因为主因，逐段互斥。因此各原因扣减合计恰等于停机分钟，效率只扣这一次；`primary_cause` 为该班实际发生停机的主因，未停机时为空。
- 影响口径（`cause_impact`/`impact`）：按原因自身有效区间的并集计，各原因互不抵消，重叠分钟会同时计入多个原因。因此影响合计可以大于停机分钟，`overlap_minutes`/`overlap` 即两者差额，仅用于维修复盘时看清每种原因各覆盖多久，不参与可用率与OEE。
- 不变量（`attribution`）：`primary_ok`（扣减合计=停机分钟）、`impact_ok`（每个原因影响≥扣减）、`overlap_minutes`（影响合计−停机分钟）。原因改写先后顺序、重复同因区间或重跑，均不改变扣减归属，也不重复扣减；原始停机记录逐条保留在 `stops`，含原区间、裁剪后区间、裁剪时长 `span_minutes` 与扣除休息后的有效时长 `minutes`，越界记录也保留并记 0。


原始行号对应 CSV 解析器的物理末行。UTF-8 BOM 与 GB18030 均支持，坏行进入隔离区，结构性错误返回422。空文件、仅表头和全空记录分别返回不同原因码。金额与用量使用 Decimal，对外以字符串返回。编码和编号按字符串保留。

run_id 由输入摘要、参数和规则版本生成；revision 为人工复核版本。证据 CSV 含运行号、来源行、原因码、原始字段及最终结论。
